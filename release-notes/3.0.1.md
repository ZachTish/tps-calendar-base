# TPS Calendar Base 3.0.1 — Base-owned drag creation

Dragging an empty time interval to create a note no longer bypasses the Base and forces GCM's calendar-event classification. User creation follows the active Base/view defaults, selected template and configured start/end-or-duration properties. A Base/template with no kind default adds no kind; a template's custom kind remains intact. Controller import storage mode does not select a writer for these new notes.

The same correction covers file/template drops and toolbar New. Active-view defaults take priority over Base defaults and remaining runtime sources, retaining ordered OR/any branch selection. Toolbar New passes a filename to Core Bases rather than repeating its inferred folder. Existing imported Calendar events keep verified identity-aware schedule updates; ordinary notes use the view's configured fields. Canceling creates nothing. No settings migration, automatic remediation, new listener, timer, cache, watcher, scan or background writer was added. The forced native creator and unused creation-payload utility were removed.

## Compatibility and limits

Backward-compatible configuration correction (patch), minimum Obsidian **1.10.0**. Existing settings destinations/mobile CSS and imported-note state are unchanged. Filter-derived assignments retain the existing conservative positive-equality behavior: date comparisons, negations, substring expressions and arbitrary formulas are not general-purpose creation instructions. Use the Base's supported equality defaults or a chosen template for explicit content. No existing note is repaired or reclassified. Physical iPhone acceptance remains unverified. Production installation is the user's BRAT pull.
