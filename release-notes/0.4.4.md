# TPS Calendar Base 0.4.4

## Intent

Restore accurate task-event durations in Calendar Base and make authored intervals visually proportional at every zoom level.

## Changes

- Task intervals are row-owned. A containing storage or Daily Note can no longer replace or supply a child task's duration through same-named frontmatter.
- Interval precedence is now explicit: the per-view fixed duration, the configured task duration/end field, canonical `[timeEstimate:: minutes]`, then the readability fallback only when no usable interval exists.
- Duration-mode task fields accept literal or formula values. End-datetime mode uses a valid row end and falls back to canonical `timeEstimate` for missing or invalid ends.
- Timed task resize always refreshes canonical `timeEstimate`; a distinct duration field receives minutes and a distinct end field receives a formatted timestamp. Timed-to-all-day removes duration/end values and records the configured all-day flag; all-day-to-timed removes that flag so the task cannot snap back.
- Both standard and continuous FullCalendar renderers set the harness minimum to zero. Explicit intervals bypass Calendar's CSS/inline readability floor, preserving proportional 15-, 30-, 60-, and 90-minute geometry.
- The existing `minEventHeight` setting is now honored per view and is presented as **Fallback event height**. It applies only to entries without an authored duration or usable end, supports zero, and remains stored under the same key.

## Compatibility and migration

- Backward-compatible patch; no settings migration, command change, Base-schema change, plugin API change, or task-syntax change.
- Existing `minEventHeight` values remain valid and now have their documented fallback-only behavior.
- Minimum supported Obsidian remains 1.10.0.
- The existing GCM 1.17.1 requirement for synthesized task metadata remains unchanged.

## Validation

- Focused regressions cover literal minutes, unit and case variants, hidden-comment fields, containing-note conflicts, custom duration precedence, formula duration, fixed per-view duration, explicit/missing/invalid end timestamps, canonical fallback, missing-duration readability, timed resize, timed/all-day round trips, exact event dates, standard and continuous FullCalendar harness configuration, embedded CSS, and per-view/global fallback-height resolution.
- All 178 declared Calendar tests, TypeScript, the mandatory separate production-mode build, byte-for-byte test-runtime artifact comparison, a full test-vault reload, and live Calendar inspection passed before publication.
- A synthetic Calendar Base showed distinct proportional 15-, 30-, 60-, and 90-minute task bars while its containing note deliberately held a conflicting five-minute estimate. The temporary fixture was moved directly to `_archive` after verification.
- Test runtime state was preserved. Production was not accessed.

## Known limitations

- An entry with no authored duration or usable end still receives the configured fallback duration/height so it remains selectable.
- Formula-backed date/duration fields remain computed and read-only; mutation requires writable task fields.
