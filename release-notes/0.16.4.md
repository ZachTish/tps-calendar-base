# TPS Calendar Base 0.16.4

Calendar views now register when loaded, so unused Bases factory candidates are not retained as active views after tabs close. Direct Calendar embeds use Obsidian Component load/unload, releasing their registered listeners on replacement and close.

This is a backward-compatible lifecycle fix. No settings, defaults, note data, provider calls, API signatures or migration change. Minimum Obsidian: **1.10.0**.

## Validation

- Four actual-source lifecycle regressions failed before the correction. They cover 50 unused factory candidates, 50 native open/close cycles, 25 direct embed replacements and independent ownership. Host Component/DOM/query boundaries are mocked.
- All **345 declared tests** passed, with zero failures, skips or cancellations. An older source assertion requiring the incorrect direct `onunload()` call was updated to require the public lifecycle methods. TypeScript and the separate final production build passed.
- Named Test plugin reload verified 0.16.4. Actual Calendar link opens and a note containing Calendar/table embeds still showed all 48 synthetic events. The active registry returned to **zero** after native switching and after closing the embedded-note tab; the prior build retained two unloaded candidates after closure.
- The installed direct-render API was exercised with real Component semantics and no vault/provider mock: three renders retained one loaded view with 15 registered cleanup callbacks. Each replacement reduced the prior view to zero callbacks; final unload left zero callbacks and zero registered views. This is an API lifecycle check, not a user-input timing sample or a filter-semantics test.
- All eight monitored settings remained identical. Original view restored, diagnostics removed, 53 fixtures archived with exact final bytes. All Markdown bodies and 48 event notes were preserved. Existing initialization added a current date to the Calendar Base, normalized table column identifiers and supplied the launcher's title; those changes were retained and recorded separately.

## Performance boundaries

This removes retained objects and skipped listener teardown; it does **not** claim faster initial rendering. Warm foreground Calendar samples were 379 ms before and 515/725 ms after, with one core Base inventory and roughly 38,300 metadata inspections each. The repeat still had three Calendar refresh/render passes. These small unmatched samples vary and do not establish a latency regression or improvement from this change. The after samples included 50–70 ms long tasks; their attribution remains open. The visible embedded Calendar was ready at 609 ms; the below-fold table was lazy and is not counted as fully verified.

Scroll automation failed to deliver wheel input; PageDown did not move the focused view. Those attempts are excluded. Desktop narrow panes are not physical iPhone acceptance. Comparable native baselines, cold startup, remaining interaction coverage and the overall 80% goal remain unverified. Existing dependency advisories were reported by the dependency helper; no dependency versions changed.

Tested in **Obsidian Plugin Test Vault**, ready for the user's **BRAT pull**. Production was not inspected or deployed.
