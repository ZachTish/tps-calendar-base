# TPS Calendar Base 0.3.4

## Intent

Keep every Calendar surface on the user-selected local calendar day across Base filters, host-note embeds, responsive layouts, saved state, and public navigation.

## User-visible fixes

- Bare `YYYY-MM-DD` values are parsed as local calendar days rather than UTC instants, eliminating prior-day shifts in timezones west of UTC.
- Date-filter equality produces a one-day Calendar range, strict upper bounds no longer add the excluded boundary day, and one-sided ranges use matching entries for their unresolved side.
- Nested filter logic retains its meaning: AND groups intersect, OR groups use a union envelope, and NOT/unresolved/contradictory ranges fail open instead of inventing a one-day lock.
- Whole-day, week, and month relative expressions preserve local calendar dates across daylight-saving transitions; month-end arithmetic clamps to a valid target day.
- The visible `tps_viewMode` option wins over legacy aliases, including `filter-based`.
- Responsive 1/2/3/7-day time grids and display-setting remounts retain the latest intended anchor, without replaying stale parent or jump state.
- The calendar date picker moves the rendered FullCalendar grid immediately.
- **Start on host note day** uses the actual containing note once and is no longer overwritten by an unrelated active Markdown note.
- Saved calendar position now uses a timezone-stable local date key. Legacy ISO saved dates remain supported.
- Public `navigateToDate(...)` and default-calendar navigation use the same local-date parser.

## Compatibility and migration

- Minimum supported Obsidian version: 1.10.0.
- No settings or note-data migration is required.
- Existing ISO `tps_currentDate` values remain readable and are rewritten as `YYYY-MM-DD` after the next navigation.
- No commands or public API names changed.

## Validation

- Focused timezone/date-filter, nested range-tree, daylight-saving, responsive-anchor, stale-prop, host-scope, view-mode precedence, date-picker, and public-navigation regressions passed.
- The complete declared test suite, TypeScript check, and separate production-mode build passed against the final versioned source.
- Obsidian 1.12.7 was reloaded in `Obsidian Plugin Test Vault`.
- UI checks confirmed the permanent three-day fixture, Previous/Next/Today behavior, display-setting remount anchoring, and synthetic strict, OR, one-sided, and zero-result additive future-date windows. The permanent fixture state was restored and the synthetic files were moved to `_archive`.
- Runtime-owned `data.json` remained absent; no settings, credentials, feeds, or outbound automation were changed.
- Production was not accessed.

## Known limitations

- The operating system's native date-picker popup is not fully automatable through macOS accessibility; the picker handoff is covered by source routing and shared-anchor tests, while its adjacent Previous/Next/Today paths were exercised in the reloaded UI.
