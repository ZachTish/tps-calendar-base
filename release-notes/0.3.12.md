# TPS Calendar Base 0.3.12

## Intent

Restore the selected-day-first meaning for manual multi-day calendars after 0.3.11 unintentionally made the saved date a centered focal day.

## User-visible fixes

- Manual `2d` through `7d` views now render the selected, saved, Today, or date-picker day as the first visible column. Selecting Friday in `3d` renders Friday through Sunday.
- Previous and Next move that first day by the configured navigation step without an extra centering offset.
- Responsive partial-week embeds keep the selected day first when their visible column count changes.
- Automatic filter-based ranges with explicit bounds remain start-anchored, and complete seven-day weeks remain aligned to the configured first weekday.
- Rendered-start persistence round-trips the same selected first day through reloads and FullCalendar remounts.

## Compatibility and migration

- Minimum supported Obsidian version remains 1.10.0.
- No settings, Base-schema, command, plugin-API, or note-data migration is required.
- Existing `tps_currentDate` values retain the same date; manual multi-day views now display that date as their first column.

## Validation

- All 132 release-declared tests passed from an isolated clean validation tree, including date-only parsing, one-through-seven-day exact spans, strict/equality/AND/OR bounds, spring/fall daylight-saving transitions, all manual day counts, selected-date persistence, responsive partial weeks, Monday/Sunday week starts, and navigation lifecycle coverage.
- TypeScript and the required separate production-mode build passed. The candidate atomically deployed only `main.js` and `manifest.json` to the test vault; the bundled and shared styles remained byte-identical.
- After a forced reload in Obsidian 1.12.7, the saved Jul 31 manual three-day fixture rendered Jul 31–Aug 2. Next rendered Aug 1–3 and Previous restored Jul 31–Aug 2. Exact filters remained Jul 31–Aug 1 and Jul 31–Aug 5, while the Monday-first week remained Jul 27–Aug 2.
- Every inspected fixture retained `tps_currentDate: 2026-07-31`; no notes, settings, feeds, or outbound automation changed, and production was not accessed.

## Known limitations

- Entry-derived filter-based views still preserve the user's navigated date when matching records change; only explicitly bounded automatic ranges snap to their derived lower bound.
