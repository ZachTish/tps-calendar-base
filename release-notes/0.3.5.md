# TPS Calendar Base 0.3.5

## Intent

Make full Calendar refreshes faster and internally coherent without removing or changing any released feature.

## Performance and reliability

- Each local note now captures one Obsidian metadata-cache snapshot and reuses it for title, start-date fallback, all-day state, status, and priority.
- A normal scheduled note with configured status and priority now performs `1` metadata-cache read instead of `3`.
- A filename-derived all-day note now performs `1` metadata-cache read instead of `4`.
- One coherent snapshot prevents a rendered entry from combining a title from one cache version with status, priority, or all-day state from later versions.
- The production bundle is smaller because three redundant cache reads and their temporary cache variables were removed. No replacement cache, persistent state, monkeypatch, compatibility shim, or fallback was added.

## Compatibility and migration

- Minimum supported Obsidian version: 1.10.0.
- No settings, commands, public API, schema, or note-data migration changed.
- Status and all-day keys retain case-insensitive lookup.
- Priority retains its existing exact-key lookup.
- Filename-derived all-day entries remain supported.
- Metadata-event fast refresh remains independent and unchanged.
- External feeds and outbound automation were not enabled during validation.

## Validation

- The new focused regression was run first against exact public 0.3.4 and failed with three cache reads in the local-entry loop; it passes after the optimization with one.
- An actual-class differential probe compared exact 0.3.4 with 0.3.5 across timed dates, Base date-only values, filename/all-day fallback, mixed-case status, exact-key priority, false/zero values, and missing frontmatter.
- Across 5,005 differential executions, rendered probe outputs had zero mismatches while metadata reads fell from 16,016 to 5,005, a 68.75% reduction.
- A rotating-cache probe confirmed 0.3.5 derives title, all-day state, status, and priority from one coherent version.
- The complete final versioned test suite, TypeScript check, separate production-mode build, test-vault reload, UI comparison, and fresh release-download verification are recorded in the published release.
- Runtime-owned state remained unchanged, and production was not accessed.

## Known limitations

- The operation-count reduction is deterministic; wall-clock impact depends on vault size, Obsidian cache behavior, device, and how many Calendar entries are refreshed.
- This patch intentionally does not alter legacy or cross-plugin fallback behavior because none was proven safe to remove within this scoped optimization.
