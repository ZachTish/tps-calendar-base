# TPS Calendar Base 0.10.4

Embedded timelines that include today now return to the current time 20 seconds after scrolling stops. Scrolling again restarts that embed's countdown; multiple embedded calendars have independent timers. Pointer holds delay the return, touch momentum counts as scrolling, and programmatic scrolling does not create a feedback loop.

A freshly rendered or reopened page starts eligible embedded calendars at now. Past/future-only ranges and month views are excluded, and no automatic date navigation occurs. Continuous timelines use today's rendered block, cancel stale centering callbacks, and retain scrolling inside the embed on mobile. Dedicated calendars retain their existing behavior, including the 30-second timer.

This is a backward-compatible fix for embeds being excluded from automatic return. No settings migration, new saved fields, note changes, or new commands. Minimum Obsidian remains 1.10.0. Configured visible hours still bound the time position.

Validation: 281/281 declared tests passed with zero failures or skips, including 22 new timer/continuous behavioral regressions. TypeScript and the mandatory separate production build passed. Final artifacts match the deployed Obsidian Plugin Test Vault files byte-for-byte; explicit Calendar reload verified 0.10.4. Real reading-mode UI tests confirmed separate 20-second deadlines, scrolling again postponing only one embed, exclusion of a September 1 range, reload positioning, and continuous return without changing its date. A 390 px host kept a bounded 360 px scroll surface with equal 388 px client/scroll widths. Mobile code paths are component-test covered; visual width testing used desktop Obsidian 1.14.1. Saved plugin settings were unchanged; temporary emulation/styles were restored and fixtures/report archived directly under _archive/Calendar Now 0.10.4 QA.

Page refresh means recreating the embedded page (reload, reopen, or rerender). Ordinary Obsidian query updates and the shared GCM refresh event do not identify explicit page refreshes and preserve scroll instead. Device-specific refresh gestures that retain the same page instance have not been independently validated.
