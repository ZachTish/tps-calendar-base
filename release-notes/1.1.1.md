# TPS Calendar Base 1.1.1 — Configured fields for existing-note ranges

Dragging a Calendar range to **Track existing event** now writes the view's configured start field and just one configured interval field. Duration mode saves minutes; end-datetime mode saves the end datetime. Previously this action also wrote `timeEstimate` unconditionally and could create a literal `note.end` frontmatter property. The default `scheduled`/`timeEstimate` route retains its behavior. Existing notes are not automatically changed.

**Advanced → Frontmatter field names** now exposes the already-saved primary event interval field alongside the date field. Those keys provide defaults to Bases that do not choose their own start/end, including direct embeds; explicit Base choices win. Existing-note selection checks the configured start key alone. A formula-based start refuses a write. No new persisted schema, background work, or automatic repair is added.

This backward-compatible fix requires Obsidian **1.10.0** or newer. It has been tested in **Obsidian Plugin Test Vault** and is ready for the user's BRAT pull. It has not been installed in production by this release workflow.
