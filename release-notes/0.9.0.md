# TPS Calendar Base 0.9.0

Calendar now offers one consistent post-create choice for notes and task destinations: show an editable preview over Calendar, open the created item, or stay on Calendar.

- **Rules & creation → After creating an item** is always visible, including when the initial Calendar create type is **Note**.
- **Editable preview over Calendar** keeps the originating Calendar visible and asks TPS Global Context Menu 1.47.0 or newer to open its responsive local Markdown editor. The preview supports body editing, explicit close, Escape, outside dismissal, and mobile keyboard-aware placement.
- **Open created item** retains the prior default behavior. **Stay on Calendar** creates the item without opening either the note or a popover.
- The policy applies to native records, Obsidian Base toolbar creation, drag/range creation, external-event conversion, template drops, unscheduled-note drops, and the exact file that receives a new task, including Daily Notes and shared task destinations.
- Scheduling or tracking an already-existing note remains unchanged. Base toolbar note creation still uses Obsidian's native Base creation flow.
- The old task-only boolean migrates safely: disabled becomes **Stay on Calendar**, enabled becomes **Open created item**, and a missing legacy value keeps **Open created item** as the default.

This is a backward-compatible feature with no Base, note, record, command, or public Calendar API migration. Editable preview requires GCM 1.47.0 or newer; if that capability is unavailable or declines, creation still succeeds, Calendar stays active, and Calendar reports the unavailable preview once per session. Minimum supported Obsidian remains 1.10.0.
