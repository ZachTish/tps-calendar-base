# TPS Calendar Base 0.4.0

## Intent

Make synthesized Calendar records participate in custom Base formulas without copying GCM parsers, reaching into private Bases internals, or silently substituting a writable field when a computation cannot be honored.

## User-visible changes

- Top-level Base formulas can drive the configured start, end/duration, title, status, priority, all-day state, and filters for checkbox-task rows and external calendar records.
- Checkbox rows receive row-first, note, file, Base-host, task, and one-based line contexts. Task identity is additive, so a checkbox with an explicit Kind such as `project` can still satisfy task formulas and filters.
- Formula filter trees keep stored-order short-circuiting and fail closed on every evaluated error or unsupported result.
- Formula-backed fields remain computed and read-only. Calendar refuses a create, drag, or resize path that would require writing its configured formula start property.
- Calendar refreshes supported formula rows when GCM publishes its versioned API lifecycle event.
- Status choices, custom inline-property permission, parent-link policy, Daily Notes, identity, menus, task lines, checkbox mapping, formulas, and line metadata now resolve through one Calendar-owned public capability registry. The old private plugin lookup and development-folder fallback paths are gone.

## Compatibility and migration

- Minimum supported Obsidian remains 1.10.0.
- Existing settings, commands, Base definitions, note data, external calendars, and ordinary non-formula views need no migration.
- Native note formulas remain owned by Obsidian. Only synthesized task/external rows require compatible GCM formula and line-metadata APIs.
- Inline Markdown values remain strings and require explicit formula conversion when a number, date, boolean, list, or link is intended.

## Reliability boundaries

- Calendar accepts only `plugin.api.formulas` version 1 and, for line rows, `plugin.api.lineMetadata` version 1.
- Missing/incompatible APIs, formula errors, unsupported operations, invalid results, and failed configured formula fields exclude the affected synthetic row with deduplicated diagnostics.
- Calendar does not use a same-name-property fallback, copied regex line parser, temporary note, private Bases evaluator, monkeypatch, `eval`, or `Function`.

## Validation

- All 149 release-declared tests pass with zero skips, including 36 focused formula, lifecycle, configuration, creation, and failure-path checks.
- TypeScript and the mandatory separate production-mode build pass from the isolated 0.3.13-based release worktree. Stable deployment updates only `main.js` and `manifest.json` in the verified test runtime; its independent `data.json` remains absent.
- After `Reload app without saving` in Obsidian 1.12.7, the existing three-day Base remains healthy with nine native results. A temporary formula Base renders exactly two synthetic checkbox tasks at 10:00 and 11:00 with formula-derived titles, while the undated task fails closed. The fixture was moved directly to `_archive`; no note body, setting, outbound automation, or production vault was changed.

## Known limitations

- TPS Global Context Menu 1.14.0 or newer must be enabled for formula-bearing synthetic Calendar rows. Disabling it or loading an incompatible API causes those rows to fail closed until the supported contract becomes available again.
- Computed fields cannot serve as mutation targets; use a writable date property in any Calendar view intended for creation, drag, or resize.
