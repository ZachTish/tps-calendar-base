# TPS Calendar Base 0.16.5 — Stop idle Calendar rerendering

Calendars without auxiliary-date or archived-event markers no longer continuously rerender while idle. The marker effect used to replace its empty array whenever Calendar mutated the DOM; the resulting React render mutated it again. It now preserves the existing empty state and installs no marker observers for that case.

The same effect now retains its latest scheduled animation frame. Observer bursts share one measurement, and cleanup cancels pending work instead of allowing an old measurement to restore a removed marker. Real markers retain their content, geometry, date navigation and resize behavior. No new setting, persisted state, cache, watcher, timer, write path or migration is added.

This is a backward-compatible **patch**, with minimum Obsidian **1.10.0**. Tested in **Obsidian Plugin Test Vault** and ready for the user's BRAT pull. Production installation and physical iPhone acceptance are not claimed.

## Validation and measured scope

- Five actual-effect regressions cover empty-state identity, unchanged observer bursts, changed marker geometry/content, removing the last marker, pending-frame cleanup, missing hosts and off-range markers. Three empty-state checks and the queued-cleanup check fail before their respective corrections. Browser scheduling, geometry and React state identity are mocked in these tests; installed checks cover the host boundary.
- **350 tests passed**, zero failures/skips/cancellations; TypeScript, the full-suite build and separate final production build passed. Only shipped artifacts were deployed to Test; named Calendar reload verified 0.16.5. Final documentation-only build is checked for identical artifact bytes.
- Before: two-second foreground idle counters recorded 440–483 FullCalendar option resets. Hook inspection isolated 241 empty-to-empty marker state replacements; date callbacks did not repeat. A separate two-second CPU profile with no readiness polling sampled **1,454 ms in Calendar code**.
- Final build: **zero resets** in each two-second sample with empty markers, populated markers, after their removal, and in an embedded Calendar. A separate 2,002 ms idle profile sampled **no Calendar work**, with about 2,000 ms idle. All normal consumer plugins remained enabled. These small desktop samples show removal of the feedback loop, not native, mobile or whole-vault performance certification.
- The same 48-event Calendar still renders all events. Actual Next/Previous/Today actions show the expected dates and restore all 48. Final opening reached two-frame readiness at 493 ms versus 424 ms before; no opening-speed improvement is claimed. Its settled one-second tail spent 109 ms in Calendar code versus 711 ms before. The embedded Calendar reached readiness at 674 ms; its off-screen table/scroll interactions remain outside this validation.
- Two synthetic entries were injected into only the installed Calendar view model to exercise auxiliary and archived marker rendering without external providers or note edits. Both chips appeared. The intermediate early-return-only build still retained the chips after removal, reproducing the queued-frame defect; the final artifact leaves zero chips and no repeating option updates after removal. Provider classification is not being claimed from this model-boundary check.
- All 53 reactivated fixture files matched their original bytes before and after archiving. Eight consumer settings states matched, the original tab was restored, active Calendar registry returned to zero, and all diagnostic wrappers/listeners/profiler hooks were removed.
- Known limits: physical iPhone, true cold process startup, paired plain-Obsidian median/tail targets and reliable scroll coverage remain outstanding. A narrow desktop-panel navigation overflow is pre-existing and remains a separate issue. No external automation or production access occurred.
