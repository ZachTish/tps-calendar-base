# TPS Calendar Base 2.0.0 — Remove Continuous mode

Continuous mode mounted five separate FullCalendar instances initially, could retain fourteen after scrolling, and sent the full event collection to each. It is removed entirely, including its component, listeners, timers, rolling date range, duplicate callbacks and document-wide scrolling navigation. Supported modes now use the existing single FullCalendar renderer.

## Behavior and compatibility

- Global settings and both Base option definitions no longer offer Continuous. Day, 2–7 Day, Week, Month and Filter-based remain.
- Old Base values in `tps_viewMode`, `viewMode` or `viewmode` resolve to Week at the existing configuration boundary, preserving alias priority. Opening a view does not migrate or rewrite the Base.
- A saved global Continuous preference loads as Week through existing settings normalization. No new schema field, timer, listener, cache, background repair, scan or note migration is introduced.
- Core Bases displays a blank View mode field for an untouched legacy value, although the effective calendar is Week. An explicit user selection persists a supported mode through the ordinary native control.
- Regular navigation, creation, dragging/resizing, embedded responsive day counts and configured timeline date pairs retain their existing paths.
- This is a major release because the supported view-mode/API value is removed. Minimum Obsidian remains **1.10.0**. This release reduces the cost of former Continuous views; it does not promise an overall vault-performance fix.

## Validation

**353 declared tests passed**, zero failed/skipped/canceled, followed by a separate TypeScript/production build. Seven retirement regressions exercise actual settings/config methods, remaining modes, all legacy aliases, precedence, parser diagnostics, menu choices, and renderer/resource removal. Across 1,000 repeated legacy resolutions they count 2,000 bounded configuration reads and **zero note reads, inventories or writes**. Existing creation, transfer, ranges, clock, snap/resize, idle-return and protocol tests keep their supported-mode coverage. Before the implementation, six retirement checks failed as expected.

Installed **Obsidian Plugin Test Vault**, Obsidian 1.14.4:

- A named Calendar-only reload verified **2.0.0** after deployment. All eight active TPS consumers remained enabled; outbound test automation remained disabled and no real settings were changed.
- First and repeated native switcher openings of the same saved `continuous` Base produced **Week, one calendar, two entries and both event titles**. Baseline 1.1.3 produced **five calendars, two entries and both titles**.
- Week Next moved October 5–11 to October 12–18; Previous returned both events. Month rendered October and both events. The legacy Base embed rendered both events in Live Preview and Reading with the existing responsive two-day presentation.
- Global settings and native Base menus list every remaining mode and no Continuous option.
- Six synthetic files remained byte-identical, including the old Base value, event dates and note body. Eight consumer data/settings hashes and the enabled-plugin list remained identical. Diagnostics were restored/removed, inactive fixtures moved directly to `_archive`, the original note and edit mode restored.
- Production was not inspected, deployed or reloaded during this task. The previous dirty canonical checkout was preserved; this release comes from a clean branch based on current `origin/main`.

### Work counts and timing limits

| Installed repeated open | Calendar instances | Calendar data passes / render requests | Raw reads / cached reads across all consumers | Inventories / metadata inspections across all consumers | Note creates / modifies / processes / renames / frontmatter attempts |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1.1.3 Continuous | 5 | 2 / 2 | 1 / 24 | 2 / 76,662 | 0 / 0 / 0 / 0 / 0 |
| 2.0.0 legacy → Week | 1 | 2 / 2 | 1 / 3 | 2 / 76,458 | 0 / 0 / 0 / 0 / 0 |

The measured renderer count reduction is attributable to this retirement. Data/render pass counts do not decrease. Global reads, inventories and metadata counts include Quick Switcher and other enabled plugins; index warmth and action duration differ and their differences are **not attributed to Calendar**. Warm-host first use after the named reload also produced one calendar, two passes/renders, one raw read, 25 cached reads and zero writes. The baseline first-use sampling interval was longer and interrupted by window focus changes, so it is not a latency comparison.

Foreground repeated-open 16 ms heartbeat maximum gaps were 81.3 ms before and 74.0 ms afterward; observed host long tasks were one 50 ms task before and none afterward. These single instrumented samples add overhead and do not establish statistical speedup or CPU attribution. Window visibility/focus was checked and background heartbeat samples excluded. This covers installed desktop Obsidian, not a cold application launch, physical iPhone or production vault. Native creation was not performed for this display-only retirement; unchanged creation/drag/resize contracts are covered by the existing tests.
