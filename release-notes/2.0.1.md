# TPS Calendar Base 2.0.1

Dismissing **Event in Past** now cancels creation and releases its in-progress guard, so a subsequent event can be created. This backward-compatible correctness patch restores the existing modal cancellation behavior; minimum Obsidian remains **1.10.0**.

## Cause and change

The past-event modal assigned an empty instance `onClose` handler during `onOpen`. That assignment shadowed its existing cancel resolver. Closing through the host dismissal left the first creation waiting indefinitely; its `finally` could not release `createInProgress`, and later creation attempts were rejected by the same guard.

The fix deletes that overriding assignment. The existing `onClose` resolves cancellation and creation's existing `finally` releases the guard. **Yes, Complete**, **No, Active** and **Cancel** retain their explicit results. The ordinary whole-note `NewEventService` owns this prompt; GCM native-record creation is unchanged. No setting, default, API, property mapping, saved-note format, timer, cache, listener, scan, retry, repair or migration is added.

## Regression validation

The focused baseline on 2.0.0 passed **13 of 15 checks** and failed the two dismissal checks. The fixed source passes **15 of 15**. The new tests execute the actual anonymous modal `onOpen` and `onClose`, and actual service creation, against synthetic host DOM/vault boundaries. They cover dismissal followed by creation, all three explicit buttons and a burst of 25 dismissals. The burst performs zero source reads, cached reads, inventories and write attempts, followed by one successful synthetic note creation; existing explicit choices survive cancellation invoked during close.

The versioned declared suite passes **358 of 358 checks**, with zero failures, skips or cancellations. TypeScript, the suite build and a separate build passed with `TPS_NO_DEPLOY=1`. An ordinary build subsequently deployed only to Obsidian Plugin Test Vault (`target=test`), and a Calendar reload loaded 2.0.1.

## Installed native-dialog QA

An isolated instance of the loaded installed `NewEventService` displayed the real native **Event in Past** modal in the foreground test vault. Native **Escape** settled the pending operation as `null`; `createInProgress` was false afterward. The same installed service then created a future event through its actual `createEvent`, `finally`, frontmatter and path helpers, returning one synthetic file. Counts were one folder preparation, one synthetic create and one linter boundary; the final in-progress guard was false.

Folder/create/linter mutation boundaries were synthetic. There were **zero real note mutations and zero network calls**. This proves installed native dismissal and service-guard recovery, not persisted end-to-end Base creation. The pre-existing Calendar Base was visible with zero events; event display, physical iPhone/iPad behavior and input latency were not established by this check. Evidence is retained in `.plugin-dev-cache.nosync/feature-retirements-20261007/calendar-past-prompt-installed-result.json` in the test vault. Production was not inspected or changed.
