# TPS Calendar Base 0.16.3

Resizing an event no longer briefly restores its old end time while Base metadata catches up. Calendar previously considered a pending change complete as soon as its start matched; an end-only resize therefore discarded its own optimistic interval. The existing acknowledgement now checks both endpoints. Partial start/end updates and a newer resize stay protected until the complete interval is visible.

This backward-compatible patch preserves the existing one-second comparison tolerance, five-second expiry and omitted-end behavior. No settings, schema, migration, extra timer, watcher, cache, repair or refresh owner is added. Minimum Obsidian: **1.10.0**.

## Validation

- Eight new regressions execute the actual Calendar update and refresh methods with real date/interval parsing. Five failed before correction; all eight pass. Coverage includes stale/partial/settled results, duration-derived ends, optional ends, superseding edits, expiry, tolerance and one write per user edit through refresh bursts. Provider writes and unrelated host rendering are mocked in these tests.
- Full declared `npm test`: **341 passed, zero failed/skipped**. TypeScript and the mandatory separate production-mode build passed; final build reports `target=test`, unchanged from the UI-tested artifact.
- Named test-vault Calendar reload verified 0.16.3. With GCM 3.6.12, Navigator 7.0.8, Health 3.8.2, Controller 2.6.3 and Finances 1.11.2 enabled, actual foreground longer/shorter resizes kept the requested interval through all four render requests. Two-frame correct layout followed confirmation in **48.2/47.5 ms**, versus **247.6 ms** with a stale interval on 0.16.2. The native write itself stayed about 36–38 ms; this fixes premature visual acknowledgement rather than disk-write speed.
- Each edit made one write, two full Calendar data passes and four render requests. Bodies, native identity and six plugins' settings were preserved. The left sidebar was collapsed for Calendar geometry and restored; all consumers stayed enabled and outbound services stayed off. Fixtures were archived after awaiting the core Base save, and final bytes verified. No long tasks or outside-fixture note mutations were observed.

## Limits and remaining investigation

These are small instrumented warm desktop samples in **Obsidian Plugin Test Vault**, not a native-performance baseline, physical iPhone or production benchmark. The first existing-record move separately took 4.8 seconds, with 4.77 seconds in GCM global identity verification reading 10,678 Markdown sources. That authority contract is unchanged by this release. First-use/global verification, cold startup and wider interaction performance remain open. Existing refresh counts are also unchanged; no speculative refresh suppression was added.

The test-vault plugin is installed and verified. This public release is ready for the user's **BRAT pull and acceptance**; it does not install or reload production.
