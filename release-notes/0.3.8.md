# TPS Calendar Base 0.3.8

## Intent

Make every Calendar Base show the exact days its view represents, including after switching views and across midnight or daylight-saving boundaries.

## Changes

- Preserves every exact filter-derived span from one through seven days instead of rounding two days to three or six days to seven.
- Adds explicit `2d` and `6d` per-view options alongside the existing day-range modes.
- Resets automatic range state when the selected Base view changes and remounts its Calendar renderer, preventing the previous view's range or centered date from leaking into the new view.
- Cancels and identity-scopes delayed date persistence so a save queued by the old view cannot write into the newly selected view.
- Derives occupied days from the same half-open interval and configured all-day property used by rendering and visible counts.
- Keeps midnight ends on the prior occupied day and preserves whole local-day all-day durations across both daylight-saving transitions.
- Keeps responsive week navigation start-anchored when constrained embeds reduce their visible day columns.

## Compatibility and migration

- Backward-compatible patch; no settings, commands, API, Base schema, or note-data migration.
- Existing saved day, three-day, four-day, five-day, seven-day, week, month, continuous, and filter-based modes remain valid.
- Minimum supported Obsidian version: 1.10.0.

## Validation

- All 130 release-declared tests, three containment checks, and TypeScript passed. Coverage includes every exact one-through-seven-day mapping, configured note/task/formula all-day values, strict half-open midnight ends, spring/fall DST spans, delayed-save isolation, mode persistence, and semantic anchor round-trips.
- A separate production-mode build deployed the final versioned artifacts to the test vault, followed by `Reload app without saving` in Obsidian 1.12.7.
- Test-vault UI QA confirmed exact July 31–August 1 and July 31–August 5 headers, one-day all-day and timed midnight-boundary views, a stable six-day-to-one-day switch, Monday–Sunday dedicated week navigation, and a two-column constrained week embed.

## Known limitations

- Filter-based views without explicit date bounds derive their initial span from currently matching local entries; an empty result set falls back to today.
- Constrained markdown and Canvas embeds may intentionally reduce the visible day columns for readability. Dedicated Calendar Base tabs preserve their configured day count.
- Continuous-scroll mode does not use a finite automatic day range.
