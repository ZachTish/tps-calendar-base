# 0.15.0 — Shared note creation opening

Calendar now uses TPS Global Context Menu's shared post-creation preference, so Calendar and embedded Tables can choose the same editable preview, open, or stay outcome.

- **After creating an item** links directly to GCM's **Note opening** settings when GCM 2.5.0+ is available.
- Every Calendar creation dispatcher supplies the created file and originating surface to the shared owner. Existing daily/task destination notes do not enter filename rename mode.
- Supported native Base creation is presented once by GCM; Calendar skips its legacy create/open observer. Older native menus retain the observer fallback and restore the originating Calendar before shared presentation.
- Existing settings remain available as fallback with older/disabled GCM; creation defaults, folders, templates, schedules and record identity are unchanged.

Validation: all 301 tests passed; separate production build, test-only deployment and reload passed. Live embedded Calendar creation retained the Calendar, created one canonical calendar-event with stable identity/schedule, and showed the shared preview. The settings handoff reached GCM. Dependency cache preparation and the final rebuild produced byte-identical tested artifacts. Test preferences and temporary record storage were restored; fixtures were archived.

Known limitations: install GCM 2.5.0+ for the shared behavior. Physical iPhone acceptance remains pending. Older/disabled GCM keeps Calendar's legacy preference and behavior.

Backward-compatible minor feature release. Minimum Obsidian: **1.10.0**. Tested in **Obsidian Plugin Test Vault**, ready for the user's BRAT pull. This release has not been installed in production by the agent.
