# TPS Calendar Base 0.4.2

## Intent

Restore reliable inline-task visibility when one source note cannot be safely scanned, without weakening the protected-Markdown boundary introduced in 0.4.1.

## Changes

- A throwing or malformed GCM document scan now skips only its own source note.
- Valid scheduled tasks collected from other notes remain visible across the same refresh and later refreshes.
- The failed source continues to fail closed, and the existing diagnostic remains deduplicated.

## Compatibility and migration

- Backward-compatible patch; no settings, Base, note, task, API, or stored-data migration.
- Minimum supported Obsidian remains 1.10.0.
- TPS Global Context Menu 1.17.0 remains required for synthesized inline tasks. Calendar does not restore the unsafe raw-line fallback removed in 0.4.1.

## Validation

- Focused two-source tests cover both a thrown scanner error and malformed physical-line coordinates, including repeat refreshes and diagnostic deduplication.
- All 160 declared tests, TypeScript, and the three contained-workspace checks passed. A separate production-mode build was deployed to the isolated test runtime and verified byte-for-byte.
- Obsidian 1.12.7 was reloaded in the test vault; the scheduled-task fixture remained visible as one calendar event. The temporary fixture was moved directly to `_archive`, runtime state was preserved, and production was not accessed.

## Known limitations

- Task rows from the individual note that cannot be safely scanned remain suppressed until its scanner failure is resolved.
- Inline task events still require the coordinated GCM scanner; native note and external-calendar rows continue independently.
