# TPS Calendar Base 0.16.2

New native Calendar events use GCM's existing fresh-identity creation contract when it is explicitly available. Calendar previously invoked the verified-ID route without supplying an ID; the first event could wait for authoritative identity verification across every Markdown note before the file was created.

Calendar selects `createFresh` only when `freshIdentityCreates === true` and the method is callable, preserving its provider receiver. Older providers continue through `create`. A failed fresh creation is reported directly and never retried through the other creator. GCM still owns ID generation, in-flight reservations, known conflicts, path allocation, initial content, indexing and notifications.

Timed/all-day fields, associated-note links, mutation attribution, canonical record/TFile validation, shared preview/open/stay behavior and existing-record edit/resolve paths are unchanged. External synchronization remains Controller-owned. This backward-compatible patch adds no settings, defaults, migration, repair, cache, watcher or timer, and does not alter Calendar refresh subscriptions. Minimum Obsidian remains **1.10.0**. The faster path needs GCM's additive fresh-identity capability; older providers remain supported through their existing route.

## Validation

- Twenty new regressions execute the actual Calendar creation method, selected from the TypeScript AST, using real payload and returned-record helpers. Seven fresh-route assertions fail against 0.16.1; all **25 native-boundary checks pass** after correction.
- Coverage includes advertised/absent/false/nonboolean capabilities, missing/noncallable methods, receiver binding, unchanged timed/all-day and associated-note payloads, source attribution, rejection without a second write, invalid handles and invalid input before any creator call.
- The installed 0.16.1 test-vault baseline recorded one cold identity refresh lasting **3,403.4 ms** before the write; the second verification reused the current index in **0.1 ms**. Whole-flow read counts are not phase-attributed and are not claimed as exclusive native-creator disk I/O.
- All **325 versioned tests passed**, with no failures or skips. The full-suite run initially caught one existing source assertion that required the old direct call syntax; it was updated to the receiver-preserving call and the complete suite rerun successfully. TypeScript, a separate build-only check and the final normal build passed. The normal build deployed changed artifacts only to `tps-calendar-base` in Obsidian Plugin Test Vault; named Calendar reload verified 0.16.2.
- Two actual foreground Base New actions passed with GCM 3.6.10, Navigator 7.0.7, Controller 2.6.3 and Health 3.8.1 enabled. A normal named GCM reload established a cold authoritative identity index; no private index reset or crypto override was used. Both actions invoked `createFresh` exactly once, with **zero identity-refresh calls and zero native source reads**, retaining the cold index afterward.
- Creation took **54.4/53.8 ms**, versus the earlier **3,449.4 ms** cold-index sample. Shared preview completed at **96.6/95.9 ms**, versus 3,485 ms before. First positive-size event DOM appeared at **284/345 ms**, versus 3,719.7 ms. These are instrumented test-vault samples, not a distribution, compositor-paint measurement or native-performance comparison. The first after sample used a shorter window; the repeat matched the baseline viewport exactly. Both were visible/focused, with no observed long tasks.
- Each action created one secure-UUID event and preserved its title, scheduled/end interval, configured filename and empty body. There were no outside-fixture writes. During each creator span, two raw reads and 22 cached reads were observed across all enabled consumers; those inclusive counts are not attributed exclusively to GCM. Whole capture totals include delayed/background work. Calendar still executed five core/render-request passes; this release does not claim to eliminate that separate work.
- The QA allocator changed only the exact synthetic record's destination to Inbox, synchronously restoring the existing path accessor before returning; no plugin setting changed. Both previews were dismissed via the UI, all hooks removed, prior leaf/search and full-screen mode restored, and fixtures archived directly. Five persisted plugin settings files remained byte-identical across deployment, reload and QA. An initial hidden-window setup stopped safely before creating a fixture and is excluded from timing.

Production installation remains the user's BRAT pull and acceptance. Physical iPhone behavior is not verified by the desktop test-vault checks.
