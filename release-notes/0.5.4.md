# TPS Calendar Base 0.5.4

## Intent

Keep drag-created and manually created Calendar tasks in the Daily Note's scheduling section instead of accidentally placing them under the note's final unrelated heading.

## Changes

- Daily Note task creation writes into the exact case-insensitive `## Scheduled` section.
- Calendar-created task lines are inserted by their configured scheduled property in descending time order: future/later events at the top and past/earlier events at the bottom.
- When that section is absent, Calendar appends a new `## Scheduled` section while preserving existing content and headings.
- Calendar recognizes the canonical scheduled-date Daily Note and explicitly targeted notes identified by `kind: dailynote` or `#dailynote` metadata.
- Explicit dedicated task target notes retain their prior append-to-end behavior.
- The task insertion remains one atomic `Vault.process` mutation and duplicate external-event identities remain idempotent.

## Compatibility and migration

- Backward-compatible correctness patch; minimum supported Obsidian remains 1.10.0.
- No settings, commands, Base definitions, task syntax, note data, or plugin APIs change.
- Existing Daily Notes and tasks are not migrated or rewritten.

## Validation

- The full declared 20-file test suite passed, including its production build.
- The focused drag/drop and event-creation smoke matrix passed 66/66, including exact `Scheduled` placement, missing-section creation, metadata-based Daily Note recognition, future-first ordering, duplicate suppression, and dedicated-target compatibility.
- A separate final `npm run build` passed TypeScript and production bundling. The stable build deployed to the isolated Obsidian Plugin Test Vault; the source and runtime artifacts are byte-identical, and the active Obsidian window was verified as `Obsidian Plugin Test Vault` after deployment.
- Production was not accessed, deployed, or reloaded.

## Known limitations

- The destination section is the canonical `Scheduled` heading. Other custom section names are not inferred.
- Explicit non-Daily-Note storage targets continue to append by design.
