# TPS Calendar Base 0.16.8 — Leave hidden embeds idle

Opening a Reading-mode note no longer mounts another Calendar inside the hidden editor just because both belong to the active tab. Hidden/detached native Calendar views also stop starting missing-data retry chains. The existing resize callback initializes them when shown; visible missing-data retries and connected protocol/direct-embed overrides remain supported.

This patch corrects two existing guards. It adds no cache, listener, timer, state, writer, setting or migration. Obsidian still owns cached components. Minimum Obsidian: **1.10.0**. Tested in **Obsidian Plugin Test Vault** and ready for the user's BRAT pull; no production installation is claimed.

## Validation

- Four actual-method regressions cover 50-event hidden/detached bursts without query/mount/retry work, resize-based activation, retry coalescing/stopping and explicit preparation. Two fail against 0.16.7. Host DOM/timers and React/data boundaries are mocked.
- All **358** declared tests pass with zero failures/skips/cancellations. TypeScript, a separate final production build, Test deployment and a named Calendar-only reload pass.
- Trusted visible/focused installed opening: the hidden editor's two data passes and two render requests become zero; no hidden React root is created. The visible Reading Calendar retains all 48 events. Hidden and detached instances have no pending data retries. The initial visible owner still performs four data/render calls; this patch does not eliminate normal Base query and initial-layout work.
- Actual Reading → Live Preview → Reading → Live Preview switches preserve all 48 events. A synthetic title change made while Reading is hidden appears when shown; restoring it while Live Preview is hidden is likewise reflected on return. The API snapshot following one Reading-mode switch was visible but unfocused. These are functional and operation-count checks, not timing or physical iPhone certification.
- Existing connected protocol/direct preparation passes automated coverage; no new installed Canvas or protocol interaction claim is made. Core Canvas stayed disabled. All regular community consumers remained enabled and outbound automation was unchanged.
- All 54 synthetic files were restored byte-for-byte and archived. Eight consumer settings states, original leaf, zoom and bounds were preserved; active Calendar registry returned to zero, global geometry remained native, and temporary wrappers were removed. No debugger was attached in this diagnostic.

Initial owner instrumentation began at view registration, so constructor work is outside its scope. The before recorder retained calls beyond its 2.5-second end snapshot until cleanup; initial before/after counts above use the same first 2.5 seconds. Later before calls establish detached retry activity but are not paired latency measurements. No cold-start, production speedup, native-performance parity or physical iPhone acceptance is claimed.
