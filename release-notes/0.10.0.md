# TPS Calendar Base 0.10.0

This release makes a calendar note one atomic TPS record instead of a bundle of duplicated calendar identities and derived fields.

- Native Calendar creation, tracking, drop, drag, resize, and association require the exact enabled GCM nativeRecords API v6 and use its atomic create/update boundary. Updates bind the verified path and `tpsId`, preventing a concurrent replacement from receiving a pending edit.
- GCM owns the sole `tpsId`, `kind`, and `title` envelope. Calendar stores the public interval as `scheduled` plus `end`, an optional true-only `allDay`, and an optional `associatedNote` wikilink.
- Native writes no longer add schema/timestamp envelope fields, provider occurrence aliases, `eventTitle`, `durationMinutes`, false all-day flags, or task-only association paths.
- Existing verbose records remain readable. The coordinated vault migration performs the explicit cleanup; ordinary Base rows and inline tasks retain their existing field contracts.

Validation: 253/253 declared Node checks, focused native-boundary/capability/formula coverage, no-emit TypeScript, a separate production build, byte-identical isolated test-vault deployment, reload, and integrated UI verification. Minimum supported Obsidian: 1.10.0. Known limitation: native writes intentionally fail closed until an enabled GCM API v6 provider is available.
