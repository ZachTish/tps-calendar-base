## TPS Calendar Base 0.3.2

This patch restores source-to-release reproducibility for the public `0.3.1` runtime. That release artifact included five runtime source inputs that were not present in its tag; `0.3.2` commits and tests those exact inputs without changing the shipped JavaScript behavior.

### Changes

- Calendar now honors the Base view's explicit **Show now indicator** value before falling back to the global plugin preference.
- Non-active status values are normalized once per event-render pass instead of once per event.
- Style-rule `any`/`all` matching stops after the decisive condition instead of evaluating the remaining pure conditions.
- Type-folder discovery takes one Markdown-file snapshot and traverses it once, preserving template-first ordering and the 500-option limit.
- The public source, numeric tag, and release artifact are reproducible from the same runtime inputs again.

Users already running `0.3.1` receive byte-identical `main.js` behavior; only the manifest version changes. No settings, note-data, or API migration is required. Minimum supported Obsidian remains 1.10.0.

### Validation

- All five focused now-indicator and efficiency regressions passed.
- All 94 tests declared by the release source passed, along with TypeScript and the required production-mode builds.
- The final `main.js` is byte-identical to the public `0.3.1` runtime, proving that this patch aligns source rather than introducing another runtime path.
- The test-vault runtime was reloaded in Obsidian 1.12.7. `Inbox/TishOS Phone Calendar QA.base` rendered its three-day Calendar with four results without changing settings, notes, feeds, or outbound automation.
- Calendar runtime state remained absent before and after deployment (`data.json` was not created).

The read-only UI smoke verified plugin load and Calendar rendering. The explicit Show/Hide and inherited-global combinations are covered by the focused behavioral regression rather than by changing a real Base setting during QA.
