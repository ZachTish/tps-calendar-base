# TPS Calendar Base 1.1.0 — Configurable timeline date pairs

Calendar can show a separate full event block for each configured date pair on a note. In **View & navigation → Timeline date pairs**, choose a start property, optional end or duration property, and label. An explicit end wins over duration. The Base view's own start remains the primary editable event; additional blocks open the same note and are display-only. Only configured fields are inspected, so unrelated imported date properties do not create events. A Base filter must admit the note: include `completedDate` in the filter to show a note that has no `scheduled` value.

The initial pairs are editable examples for `scheduled`/`timeEstimate`, `completedDate`, and `startedAt`/`endedAt`/`durationMinutes`. The saved list can be empty and is limited to twelve pairs. This adds one setting, `timelineDatePairs`, without rewriting notes or saved Base views. The old clustered auxiliary marker path is removed. Default priority color rules now match exact manual `tags` values; **existing saved style rules are not rewritten** and should be changed in Appearance if the vault moves priority to tags.

This backward-compatible feature requires Obsidian **1.10.0** or newer. The separate vault migration of kind, date, tags, templates, and Base filters has not been applied by this release. A Base's primary date property remains configured in that Base view; the timeline-pair setting does not override it.

## Validation

- All **332** declared subtests across 28 files pass, including exact configured date fields, end/duration precedence, unchanged-note parsing counts, read-only secondary event conversion, tag-based style matching, and archived marker behavior. TypeScript and a separate production-mode build pass.
- The final build deployed the changed artifacts to the named **Obsidian Plugin Test Vault** runtime, which reloaded Calendar. The existing runtime `data.json` remained byte-identical.
- Installed desktop QA used a synthetic Base and two notes. The view displayed **four** full blocks: one primary scheduled event, completed and started blocks for the same note, and a completed-only note. The unconfigured `providerObservedAt` date added no block. The settings UI exposed the three editable default pairs. QA files were moved directly to `_archive` and the previous tab was restored.
- Physical iPhone behavior and the production vault's Base filters have not been verified. This release is the tested BRAT handoff; it is not evidence of a production installation.
