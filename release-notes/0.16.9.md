# TPS Calendar Base 0.16.9 — Cancel the obsolete data wait

Calendar now cancels its outstanding missing-data timer when it accepts query data. Previously it reset the retry count but left the timer armed, causing another full update after data had already arrived. The existing missing-data retry, visibility guard and normal Obsidian data notifications retain their ownership.

This backward-compatible patch adds four lines at the existing success boundary. No new timer, cache, listener, state, setting, write or migration. Minimum Obsidian: **1.10.0**. Tested in **Obsidian Plugin Test Vault**, ready for the user's BRAT pull. Production has not been changed.

## Validation

- New actual-method regression fails on 0.16.8 and passes after: 50 missing-data updates share one timer; empty and populated arrivals cancel it; draining timers causes zero extra updates; later genuine data notifications still process. Timers and the expensive processing boundary are mocked.
- All **359** declared checks pass, zero failures/skips/cancellations. TypeScript, the separate final build, Test deployment and named Calendar-only reload pass. The first full run had nine failures because older prototype-only fixtures omitted constructor timer fields. Their helper now initializes those fields exactly as the real constructor does; no production fallback was introduced.
- Installed trusted visible/focused mixed-note opening: four data/render passes become three, in both first and repeated after samples. The visible Calendar retains all 48 events; hidden views remain unmounted and no retry stays pending. A real synthetic title mutation updates the visible Calendar and restores correctly.
- Title-parser calls were 144 before and 48/96 after, with instrumented totals 37.6 ms and 10.3/17.7 ms. Early query availability differed between samples, so these are not a guaranteed percentage improvement. The first populated render request occurred at about 351 ms before and 715/303 ms after. These small samples do **not** establish faster first paint or input latency. The verified result is cancellation of one obsolete timer-driven pass.
- All regular community consumers remained enabled; outbound automation unchanged; core Canvas stayed disabled. No debugger was attached. All 54 fixture files restored byte-for-byte and archived, eight plugin disk/memory settings unchanged, original leaf/zoom/bounds restored, active Calendar registry zero and temporary wrappers removed.

Native-performance comparisons, cold process startup, physical iPhone acceptance and remaining title-parsing/visible-layout costs are still separate work. Source ownership instrumentation starts at view registration, excludes constructors and includes its own stack/timing overhead.
