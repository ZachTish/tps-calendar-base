# TPS Calendar Base 0.5.0

## Intent

Open the exact Calendar Base view on the same local day displayed by a TishOS widget without mutating the Base's saved date.

## Changes

- Adds the strict version-1 `obsidian://tps-calendar-open` navigation protocol with independent active-vault verification, exact Base/view validation, a real local `YYYY-MM-DD` day, and optional current-time scrolling.
- Waits for one exact initialized Calendar renderer and its resolved filter/navigation range before applying the requested day. Rapid requests supersede older queued or waiting requests.
- Applies external focus transiently, preserves an already earned user-date save while suppressing pending automatic saved-date writes, blocks automatic/context refreshes and stale non-user render callbacks from replacing the request, and resumes normal persistence only after explicit user navigation.
- Adds `plugin.api.openCalendarBaseAt({ basePath, viewName, date, scrollToNow? })` for trusted in-process integrations.
- Adds focused protocol, vault, date, view, lifecycle, supersession, and non-persistence regressions to the declared test suite.

## Compatibility and migration

- Additive minor release. Existing settings, commands, Base definitions, stored plugin data, notes, tasks, and saved Calendar dates need no migration.
- Minimum supported Obsidian remains 1.10.0.
- TishOS Companion 0.5.0 uses this protocol for date-aware Calendar widget root/title taps. Older TishOS releases and ordinary Base links keep their existing behavior.

## Validation

- The complete declared `npm test` suite passed, including the protocol, rendered-settlement, rapid-navigation, external-calendar freshness, timezone, hidden-renderer, mobile-open, creation, formula, and contained-workspace regressions. Its production build deployed only the changed `main.js` into the isolated test runtime.
- The required separate `npm run build` passed TypeScript and produced a byte-unchanged test deployment. Source and test-runtime `main.js` are byte-identical.
- Obsidian 1.13.7 was reloaded with `Reload app without saving` in `Obsidian Plugin Test Vault`. From a blank tab, the exact URI for `Inbox/TishOS Phone Calendar QA.base#Phone 3-Day QA` and `2026-08-14` opened the Calendar visibly on August 13–15, with August 14 centered. A wrong-vault URI was rejected and left that range unchanged.
- The QA Base retained SHA-256 `2abb5f9bd9cd1c42b3562982cfe0f56c62b593438753f556f4b8145f6391a9f7`, proving transient navigation did not edit its saved date or definition. Production was not accessed or changed.

## Known limitations

- The protocol is navigation-only and does not expose commands or mutations.
- Obsidian controls cross-app launch and Base data-preparation timing. Calendar bounds its mount, initialized-renderer, and final presentation-settlement checks separately and fails closed when it cannot prove the exact active view rendered the requested day.
- Physical iPhone cross-app timing and rendering remain a TestFlight acceptance check for TishOS rather than an automated plugin claim.
