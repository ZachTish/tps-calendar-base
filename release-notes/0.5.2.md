# TPS Calendar Base 0.5.2

## Intent

Make Calendar Base status filters deterministic for synthesized checkbox tasks while preserving ordinary note-property and explicit formula namespaces.

## Changes

- Bare `status` conditions now read live GCM checkbox workflow status on synthesized task rows and ordinary note `status` on note rows.
- Separate negative status clauses reliably exclude won’t-do (`[-]`) and migrated (`[>]`) tasks while retaining open tasks and nonterminal notes.
- Negated `containsAny` expressions now use a supported negative-any operator instead of failing closed and rendering zero rows.
- Explicit `task.status` remains the workflow namespace; explicit `row.status` and formula row context remain authored inline metadata.
- Added a production-shaped regression covering open, won’t-do, migrated, and ordinary note rows through serialized and runtime-object filters.

## Compatibility and migration

- Backward-compatible correctness patch. No setting, command, Base schema, task syntax, note data, or plugin API migration is required.
- Minimum supported Obsidian remains 1.10.0.
- GCM’s current task-checkbox mapping remains authoritative. Unmapped checkbox states are not guessed from authored metadata.

## Validation

- All 227 declared tests pass, including 32/32 focused formula/task-filter checks and the production-shaped open, won’t-do, migrated, and ordinary-note matrix.
- TypeScript passed, followed by the required separate production-mode build. The final build reported the isolated test runtime unchanged after the suite deployed the same versioned bundle.
- Source and test-runtime `main.js`, `manifest.json`, `styles.css`, and `styles-ui.css` are byte-identical.
- Interactive Obsidian QA was intentionally not attempted because the only visible Obsidian window was `TishOS v0.1` rather than the test vault. The safeguard stopped before any click or mutation; production remained untouched. The executable test exercises the exact Calendar row-admission decision without relying on visual layout.

## Known limitations

- Checkbox task status requires the compatible GCM task-checkbox capability. Structurally valid but unmapped checkbox markers remain visible and have no inferred workflow status.
- This patch does not rewrite existing `.base` files. It makes the native bare-status filters shown in Obsidian evaluate correctly for Calendar’s synthesized task rows.
