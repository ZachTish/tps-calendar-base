# TPS Calendar Base 0.5.3

## Intent

Stop legacy plain-title calendar tasks from offering duplicate note creation when Obsidian can already resolve an exact matching local note.

## Changes

- Calendar's task chooser now recognizes an exact existing note resolved from the visible task title.
- Hidden association metadata, visible links, parent-linked notes, and exact external-event occurrence identity keep their higher-priority behavior.
- A resolved title is accepted only when the note's frontmatter `title` or basename exactly matches the task title. Partial/fuzzy names remain unresolved.
- The fix does not rewrite task lines or notes and does not create, move, or delete any vault content.

## Compatibility and migration

- Backward-compatible correctness patch. No setting, command, Base schema, task syntax, note data, or plugin API migration is required.
- Minimum supported Obsidian remains 1.10.0.

## Validation

- The full declared suite passed: 231 tests, including four focused task-note association regressions.
- A separate final production-mode build and test-vault deployment passed. Source and deployed runtime artifacts are byte-identical.
- Interactive test-vault verification used a temporary production-shaped plain-title calendar task. Its context menu showed **Open associated note** for the exact existing note; the temporary QA notes were removed afterward.
- The production vault was inspected read-only to confirm the failure shape; it was not modified or deployed to.

## Known limitations

- A differently titled note still requires explicit association metadata, a visible link, an exact external-event identity, or the existing unique parent/backlink recovery route.
- Calendar intentionally does not use partial-title or body-content guesses.
