# TPS Calendar Base 0.3.6

## Intent

Reduce repeated source-URL work in external-event matching while preserving every released identity and compatibility fallback.

## Performance and reliability

- Local-note event-ID, UID, and title fallback scans now normalize the note's stored calendar source once per nonempty scan.
- Vault-wide UID/title suppression and inline-task UID matching use the same bounded normalization rule.
- Candidate event URLs remain normalized at comparison time, so no mutable external-event object is cached or rewritten.
- Empty candidate lists do not normalize the stored source. A one-candidate scan keeps the same normalization budget as 0.3.5, while longer scans remove one redundant stored-source normalization per additional comparison.
- No persistent cache, monkeypatch, global state, compatibility shim, fallback, or unsupported Obsidian action was added.

## Compatibility and migration

- Minimum supported Obsidian version: 1.10.0.
- No settings, commands, public API, schema, or note-data migration changed.
- Exact `externalId` and source-scoped event-ID matches still run before legacy/fuzzy matching.
- Legacy event-ID, UID/time, title/time, recurring drift, and `webcal://` source compatibility remain supported.
- Source truthiness and first-match ordering are unchanged, including whitespace-only legacy values.
- Archived/canceled local-note suppression and filtered inline-task suppression remain unchanged.
- External feeds and outbound automation were not enabled during validation.

## Validation

- Exact public 0.3.5 (`9889073d27b1e8d296c8b8cb68b1639c5a66c2f7`) reproduced the published `main.js`, `manifest.json`, `styles.css`, and `styles-ui.css` byte-for-byte.
- The exact-tag baseline passed all 104 release-declared tests and a deployment-disabled production build.
- Seven focused gates execute the actual Calendar local-entry, vault-suppression, and inline-task methods across all six optimized fallback branches.
- Deterministic cases preserve source identity, first-match object identity, recurring matching, and archived suppression.
- A seeded 100,000-case differential preserves exact matched-object identity and order while reducing normalization calls.
- A prewarmed, order-interleaved 15-round benchmark covers 500 records × 1,000 unmatched external events per round. Stored/candidate URL normalizations fell from 1,000,000 to 500,500 per round; median time fell from 58.059 ms to 13.908 ms (76.0%), and p95 fell from 59.414 ms to 15.223 ms.
- The isolated owned 0.3.6 candidate passed 111/111 tests, TypeScript, and the mandatory separate deployment-disabled production build. The final `main.js` is 992,507 bytes, 415 bytes larger than public 0.3.5 because the six permanent scan guards and focused helper remain explicit.
- The mandatory deployment build then passed and atomically changed only `main.js` and `manifest.json` in the isolated `tps-calendar-base` runtime; `styles.css` and `styles-ui.css` remained byte-identical.
- Obsidian 1.12.7 was reloaded in `Obsidian Plugin Test Vault`. The permanent `Inbox/TishOS Phone Calendar QA.base` rendered its configured July 16–18 three-day grid and all four expected results. No event, task, Base setting, feed, or outbound automation was changed.
- Runtime `data.json` remained absent. `.hotreload` retained SHA-256 `7caebdb9e207a5fa31de20194bd27f380a44bcb3e302634f5598823218362556` and its original modification time.
- Production was not accessed or promoted.

## Known limitations

- Wall-clock impact depends on external-event count and how often matching reaches source-constrained fallback scans. Exact-ID matches and one-event scans are intentionally unchanged.
- This patch does not index external events or combine matching stages because either change would require broader ordering and compatibility risk.
- Existing compatibility fallbacks remain in place because none was proven safe to remove.
