# TPS Calendar Base 3.0.3 — Reduce event-title parsing on reopen

A Calendar with many Base results was sending every ordinary event title through the broad daily-filename date parser before its strict whole-date check. The existing strict check now runs first. Ordinary text titles skip the broader parser; complete date titles still pass both checks. Trailing numeric/human date suffixes and custom date formats retain their existing behavior.

This is a backward-compatible performance patch. Minimum Obsidian remains **1.10.0**. No settings, schema migration, cache, observer, timer, background task, repair system or note writer is added. Base filtering, all-result navigation bounds, external/import ownership and date parsing elsewhere remain unchanged.

## Validation

- All **381** declared tests pass, with zero failures, skips or cancellations; TypeScript and the suite build pass. A separate production build deploys only to **Obsidian Plugin Test Vault**, followed by a targeted Calendar reload. The final documentation-only rebuild uses the same artifact bytes.
- Three actual-method regressions use real Moment parsing. The ordinary-title regression fails against 3.0.2: 3,676 titles enter the broad parser. With this patch that count is **zero**. Whole dates, numeric/human suffixes, ordinary titles and custom formats (including a format without a year) retain expected display values.
- Installed native-record mode uses a real synthetic Base with **3,676 rows**, a formula-derived end, and **339 events** in the displayed month. First opening and two repeated anchor→Base opens run with all eleven existing test consumers enabled. No query, parser, renderer, vault or cross-plugin boundary is mocked. Temporary method wrappers, animation-frame observations and Long Tasks observations are removed after QA. Early samples taken while fixture metadata was still indexing are excluded.

Every measured sample has the same 3,676 final entries and 339 event elements. Work counts other than title parsing are unchanged: two Calendar data calls (initial empty plus populated), two render requests, two Base-filter cached reads, one raw vault read and 76,281 metadata lookups across all enabled consumers/Core Bases. No Vault modify/process attempts occur in the samples. These aggregate counts are **not** a claim that Calendar itself performs all the metadata lookups, or that the entire opening path is now free of inventories. All 3,677 synthetic Markdown bodies and existing plugin settings are preserved; inactive fixtures are moved directly to `_archive`.

These are small, instrumented, visible/focused desktop samples in a warm Obsidian process. They establish removal of the demonstrated parsing stall and a modest overall opening improvement, **not** elimination of the remaining opening delay, exact paint latency, cold-app speed, native-view parity or physical-iPhone speed. The previous physical-phone 3.0.2 measurement was about 2.4 seconds via Mirroring; 3.0.3 has not been installed or timed on that phone as part of this release. Production is unchanged. Ready for the user's BRAT pull and device acceptance.
