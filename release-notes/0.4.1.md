# TPS Calendar Base 0.4.1

## Intent

Prevent task-shaped examples in protected Markdown from becoming scheduled Calendar events, using GCM's one authoritative document boundary instead of maintaining another partial parser.

## Changes

- Inline checkbox-task discovery now consumes only physical lines admitted by GCM `lineMetadata.scanDocument`.
- YAML frontmatter plus fenced, indented, HTML, and comment blocks cannot synthesize Calendar task events. Valid nested tasks retain their exact source-line identity and formula context.
- Removed raw regex title, inline-field, and tag fallbacks from synthesized discovery. GCM's canonical `parseLine` result is authoritative.
- Missing, incompatible, throwing, or malformed document scanning fails inline task synthesis closed with a deduplicated diagnostic. Native note rows and external-calendar events remain independent.

## Compatibility and migration

- Backward-compatible patch; no settings, Base, note, task, or stored-data migration.
- Minimum supported Obsidian remains 1.10.0.
- TPS Global Context Menu 1.17.0 must be installed first for synthesized inline tasks. An older or disabled GCM intentionally suppresses those task rows rather than risking quarantined results.

## Validation

- Focused line-metadata/formula tests cover protected-block exclusion, exact physical identities, full-document footnote metadata, missing contracts, scanner failures, malformed coordinates, and parse failures.
- The complete declared Calendar suite passes 159/159 tests, followed by TypeScript and a mandatory separate production-mode build in the isolated test vault.
- Test-vault reload and live Calendar QA confirm the eligible scheduled task remains visible and quarantined examples remain absent. Runtime-owned state remains unchanged; production is not accessed.

## Known limitations

- Inline task events depend on the coordinated GCM scanner. Native note and external event rows continue without it.
- Formula-backed mutation targets remain read-only as documented in 0.4.0.
