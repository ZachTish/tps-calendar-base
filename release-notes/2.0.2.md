# TPS Calendar Base 2.0.2

Closing the native **Convert to Meeting Note?** dialog with Escape, X or an outside click now cancels its pending operation. Previously, the dialog had no close resolver, so drag/resize callers waited indefinitely after dismissal. The owning modal now resolves cancellation from `onClose`; the explicit Convert and Cancel buttons settle their choice before closing. No extra state, cache, timer, listener, retry, repair, scan, settings field or note migration is added.

This is a backward-compatible patch. Minimum Obsidian remains **1.10.0**. Existing creation defaults, explicit choices, file creation, notices and error handling are preserved. The existing drop cancellation throws and is reverted by React; resize cancellation returns normally. This release does not change either policy.

- Seventeen focused checks execute the actual Calendar view prompt, creation handler and React confirmation/cancellation methods. Obsidian Modal/DOM and final creation/Base-refresh/open boundaries are synthetic.
- The released 2.0.1 baseline passes eleven and fails six expected unresolved-dismissal checks. After the fix, all seventeen pass with no failures, skips or cancellations.
- Escape/X/outside cancellation settles exactly once. Twenty-five dismissed prompts perform zero vault reads, cached reads, inventories or write attempts, then the next conversion creates one synthetic note.
- Explicit Convert/Cancel, null creation results, handled creation failure notices, unhandled rejection propagation and consumer revert contracts remain covered.
- All **375 declared checks** pass with zero failures, skips or cancellations. TypeScript and the suite production build pass with `TPS_NO_DEPLOY=1`, preserving the installed runtime. A separate TypeScript/production build also passes with `TPS_NO_DEPLOY=1`. An ordinary build deployed only to the verified Test vault (`target=test`), followed by a targeted Calendar reload and reopening the existing QA Base for a fresh installed view owner.

Counts from synthetic method tests are separate from installed behavior and timings. No production installation, physical-iPhone verification, external calendar sync, real event drag/resize or persisted meeting-note creation is claimed by these tests. Production installation is the user's BRAT update after the public release.

## Installed baseline

Foreground TEST QA on installed 2.0.1 invokes the actual Calendar view prototype prompt with the real native Modal and an isolated receiver whose meeting-creation boundary is a synthetic counter. Native Escape removes the visible dialog but leaves the operation unresolved: zero settlements and zero creation calls. Real note mutations and network calls are both zero. Evidence is retained in `.plugin-dev-cache.nosync/feature-retirements-20261007/calendar-conversion-installed-baseline.json`; the QA global was removed and no dialog remained afterward. This proves the installed originating close defect, not persisted meeting-note creation or real external-event drag/resize behavior.

## Installed fixed-dialog QA

The same isolated actual-prototype/native-Modal boundary on installed 2.0.2 passes foreground native Escape, Cancel and Convert. Escape and Cancel each resolve false once and make zero creation calls. Convert resolves true once and invokes the synthetic meeting-creation boundary once. An isolated throwing creation boundary preserves its original error, one settlement and one invocation. A repeated Convert also retains its result; it is not an X-dismissal test. Real note mutations, settings changes and network calls are zero. All QA globals were removed and no modal remained.

Native X/outside pointer automation was unavailable (`windowNotFoundAtPosition`), so those installed cases are **unverified**; the focused actual-method tests cover their shared host-close callback with facades. Saved evidence is in `.plugin-dev-cache.nosync/feature-retirements-20261007/calendar-conversion-installed-fixed.json` and `calendar-conversion-installed-error.json`. These installed checks do not claim real event drag/resize, persisted meeting-note creation, mobile behavior or latency.

Test-vault acceptance is complete within these stated boundaries. This release is ready for the user's BRAT pull; production installation and physical-device acceptance remain separate.
